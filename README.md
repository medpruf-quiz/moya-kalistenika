# Моя калистеника

Локальное iPhone-приложение-трекер для Scriptable.

## Архитектура

- `bootstrap.js` — стабильный загрузчик Scriptable. Проверка и установка обновлений выполняются отдельным запуском этого же скрипта через штатный URL Scheme Scriptable.
- `app.html` — интерфейс и логика приложения. Хранится локально на iPhone и может обновляться из приложения.
- `version.json` — небольшой публичный манифест версии.

## Приватность

Репозиторий содержит только код. Он **не содержит и не получает** историю тренировок, вес, талию, сон, питание, резервные копии или другие пользовательские записи.

На iPhone данные находятся в `Scriptable/Documents/MoyaKalistenika/data.json`; автоматическая резервная копия состояния на начало запуска — `data.backup.json`. При восстановлении повреждённого `data.json` исправная резервная копия не перезаписывается. Код приложения хранится отдельно в `app.html`, предыдущая версия кода — `app.backup.html`.

Интернет не нужен для обычной работы. Он используется только при первой установке локального `app.html` и при ручной проверке/установке обновления. Кнопка обновления перезапускает тот же Scriptable-скрипт с параметром; GitHub проверяется нативным `Request` до открытия WebView.

## Обновления

1. Разработчик обновляет `app.html` и повышает версию в `version.json`.
2. Пользователь открывает «Ещё» → «Проверить обновление».
3. Приложение перезапускает тот же Scriptable-скрипт в режиме `checkUpdate`.
4. `bootstrap.js` проверяет `version.json` через нативный `Request`, при наличии новой версии показывает системный диалог и после подтверждения скачивает новый `app.html`.
5. Новая версия кода сохраняется локально; предыдущий `app.html` резервируется.
6. `data.json` не заменяется обновлением кода. Если схема данных меняется, приложение мигрирует её явно; bootstrap не запускает код, который старше схемы локальных данных.
7. Перед показом новой версии bootstrap проверяет, что приложение дошло до состояния готовности; при неудаче используется совместимая `app.backup.html`, если она доступна.

GitHub Pages, Actions, backend, аналитика, база данных и аккаунты приложения не используются.


## Сохранение данных

WebView передаёт в Scriptable только изменившиеся верхнеуровневые разделы состояния; полная копия отправляется на критических границах (закрытие/перезапуск/восстановление). В состоянии используется монотонная ревизия: если локальный WebView-кэш новее `data.json`, приложение может восстановить более свежую копию и снова записать её нативно.

`data.backup.json` — стабильный снимок состояния на начало запуска, а не предыдущий ввод в поле. В разделе «Ещё» его можно восстановить отдельной командой.

Таймер отдыха дополнительно планирует локальное уведомление Scriptable. Оно не отправляет данные наружу и может сработать, даже если WebView находится в фоне.
