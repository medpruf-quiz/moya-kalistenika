# Моя калистеника

Локальное iPhone-приложение-трекер для Scriptable.

## Архитектура

- `bootstrap.js` — стабильный загрузчик Scriptable. Проверка и установка обновлений выполняются отдельным запуском этого же скрипта через штатный URL Scheme Scriptable.
- `app.html` — интерфейс и логика приложения. Хранится локально на iPhone и может обновляться из приложения.
- `version.json` — небольшой публичный манифест версии.

## Приватность

Репозиторий содержит только код. Он **не содержит и не получает** историю тренировок, вес, талию, сон, питание, резервные копии или другие пользовательские записи.

На iPhone данные находятся в `Scriptable/Documents/MoyaKalistenika/data.json`; автоматическая резервная копия — `data.backup.json`. Эти файлы не отправляются в GitHub. При восстановлении повреждённого `data.json` исправная резервная копия не перезаписывается. Код приложения хранится отдельно в `app.html`, предыдущая версия кода — `app.backup.html`.

Интернет не нужен для обычной работы. Он используется только при первой установке локального `app.html` и при ручной проверке/установке обновления. Кнопка обновления перезапускает тот же Scriptable-скрипт с параметром; GitHub проверяется нативным `Request` до открытия WebView.

## Обновления

1. Разработчик обновляет `app.html` и повышает версию в `version.json`.
2. Пользователь открывает «Ещё» → «Проверить обновление».
3. Приложение перезапускает тот же Scriptable-скрипт в режиме `checkUpdate`.
4. `bootstrap.js` проверяет `version.json` через нативный `Request`, при наличии новой версии показывает системный диалог и после подтверждения скачивает новый `app.html`.
5. Новая версия кода сохраняется локально; предыдущий `app.html` резервируется.
6. `data.json` не заменяется обновлением кода. Если схема данных меняется, приложение мигрирует её явно; bootstrap не запускает код, который старше схемы локальных данных.
7. Перед показом bootstrap проверяет пакет `app.html`; если WebView не удаётся загрузить, используется совместимая `app.backup.html`, если она доступна.

GitHub Pages, Actions, backend, аналитика, база данных и аккаунты приложения не используются.


## Сохранение данных

Нативная запись `data.json`, `data.backup.json` и `app.html` выполняется через временный файл с проверкой чтением и финальный `writeString()`, который перезаписывает существующий путь без зависимости от поведения `FileManager.move()` на устройстве.

WebView сначала синхронно записывает состояние в локальный recovery-кэш и проверяет его обратным чтением. Затем в Scriptable передаются изменённые верхнеуровневые разделы состояния; раздел, изменённый хотя бы раз за текущий запуск, повторно включается в последующие patch-записи, поэтому быстрое изменение и возврат значения не может оставить `data.json` в промежуточном состоянии. Полная копия отправляется на критических границах (закрытие/перезапуск/восстановление). В состоянии используется монотонная ревизия: если recovery-кэш новее `data.json` или при той же ревизии отличается от него, приложение восстанавливает локальный вариант и снова записывает его нативно. Если recovery-кэш недоступен, приложение сразу отправляет полный нативный снимок.

`data.backup.json` — стабильный снимок состояния перед обычной работой/обновлением, а не предыдущий ввод в поле. Копирование данных в буфер не перезаписывает этот снимок. В разделе «Ещё» его можно восстановить отдельной командой.

Полный сброс сохраняет текущие настройки профиля, передавая их только локально между двумя запусками Scriptable; отдельный файл профиля не создаётся.

Таймер отдыха дополнительно планирует локальное уведомление Scriptable. Оно не отправляет данные наружу и может сработать, даже если WebView находится в фоне.


## Правило релиза

Изменения приложения готовятся в отдельной ветке и после проверки объединяются в `main` одним squash-merge. `app.html`, `bootstrap.js` (если менялся), `version.json` и документация должны попасть в `main` одновременно. Манифест не публикуется отдельно раньше совместимого кода.


## Запуск WebView

Начальная синхронная инициализация `app.html` не обращается к нативному мосту Scriptable до завершения события `load`. Сохранение миграции, восстановление локального уведомления таймера и другие запросы к `scriptable.local` запускаются только на следующем тике event loop. Это предотвращает взаимную блокировку `WebView.loadHTML()` и служебных запросов страницы.

Bootstrap содержит узконаправленное восстановление для известной неисправной версии app 2.5.2: при её обнаружении до открытия WebView загружается совместимая исправленная версия из `version.json`; при отсутствии сети может использоваться совместимая локальная `app.backup.html`.


## Проверка обновлений и состояние данных

Проверка/установка кода приложения не заменяет `data.json`. Поэтому несовпадение WebView/native state не блокирует проверку обновлений. Если точное совпадение состояния перед update-check не подтверждено, bootstrap сохраняет существующий `data.backup.json` без перезаписи и продолжает только кодовое обновление. Для операций, где нужна точная копия данных, строгая проверка состояния сохраняется.
